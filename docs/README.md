# docs

`signal-flow-light.svg` and `signal-flow-dark.svg` are one poster of the whole
instrument's signal flow, in the printed-manual and the app's Dark colours.
`signal-flow-zones.json` lists the poster's clickable areas and every drawn
block for the in-app map: Help & About → Explore the signal flow, and a help
topic's Show in the signal flow, which rings a block by its layout id. All
three are generated by `scripts/diagram/signal-flow.mjs`. Edit the script, not
these files, then run `npm run docs:diagram`; `tests/signal-flow/assets.test.ts`
fails if the zones are stale.

The app inlines the posters, so they stay inside its Content Security Policy:
no `<style>` element, no `style=""` attribute, no external reference, and every
`id` prefixed `sf-`. The generator refuses to write a file that breaks this
(`specs/features/signal-flow-map.md`).

The poster is an illustration. The source of truth for the audio graph is
`specs/architecture.md` → "Audio graph"; when the engine changes, update the
layout in the script to match.
